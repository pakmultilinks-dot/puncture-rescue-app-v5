# v5 design review

The visual system keeps the requested warm-paper, charcoal, and vermilion palette with restrained hairlines and editorial Georgia headlines. The home screen now includes a compact three-step orientation strip—area, mechanic, preview—so the rider can understand the local-only flow before acting. The title remains focused on motorcycle punctures, with one dominant location-based action and a manual-area alternative.

Mechanic results remain open, rule-separated rows rather than generic stacked cards. Distance and ETA are presented as clearly labeled sample metrics, availability remains explicitly marked as a sample window, and each row is one tap target. The mechanic profile keeps its compact, factual open list and a single request-preview action; the status state uses a softly tinted panel and a visible **Local preview** label. The no-results state now has a quiet tyre mark and a clear recovery action without adding other service categories.

A persistent **Demo · fictional** marker and point-of-decision notes preserve the prototype disclosures. The denied-location path still lands on manual area/landmark entry. A mechanic or shop remains one unified fictional listing experience; there is no provider-type split.

The design has no real provider/location data, calls, booking, accounts, payments, dispatch, backend, onboarding, or live integrations. Location permission is requested only after the rider taps; any foreground fix is discarded and never used to match sample entries. The request and listing experiences remain local-only previews.

The updated browser suite checks 360/390/430/768 CSS-pixel layouts, no horizontal overflow, a **48 px minimum** visible button height/width, and one primary action on action screens. Ten selected normal-text contrast pairs pass WCAG AA at **4.78:1 or higher**.
